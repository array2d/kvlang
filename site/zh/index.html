一门纯文本解释型语言：代码与数据同处一棵 KV 树。

程序计数器是一条路径，源码即 IR，每个值都是纯文本——任何 KV 客户端都能查看，崩溃后可从原指令继续。

为什么是 kvlang

小核心，其余能力全部注册在路径上。

代码即数据

一个函数就是一棵子树。参数在负轴是读参、正轴是写参——与 kvspace 里每个值的形状完全一致。 


    rwfunc add(a:int64, b:int64) -> (c:int64) { a + b -> c }

PC 是路径，崩溃可续

没有独立的调用栈。帧深直接写在程序计数器里，重启后的进程可以从同一条指令继续执行。 


PC    = "/vthread/<vid>/[1]/[3,0]"            vthread vid, frame 1, instruction 3

小核心，扩展在上

核心运行时只负责执行与跳转。其余每个 opcode 都注册在 /lib/<opcode>，交给声明了它的运行时兑现。 


/lib/<opcode>/vids/<vtid> = pc

字节一致的双后端

一套 PascalCase C ABI，两个实现由 DSN 选择。同一份程序在共享内存、文件或 Redis 上运行，落盘字节完全一致。 


KVSPACE=shm:///tmp/kvlang.shm ./bin/kvlang tutorial/01-basics/hello.kv   # kvspace-c
KVSPACE=fs:///tmp/kvlang-fs   ./bin/kvlang tutorial/01-basics/hello.kv   # kvspace-durable

为 Agent 而生

源码、值与编译产物都是同一棵树里的纯文本。deepx 以 kvlang 作为前端语言；byteseek 通过同样的 KV 读写，读取并改写自己的代码与状态。

生态

三层，一棵树。每一层都可以独立替换。

kvspace

寻址与内存。一套 C ABI；shm 与 durable 后端必须逐字节一致。

layout

o0 编译器。解析源码并写入 KV 树——不做优化，没有 IR。

runtime

纯解释：取指、解码、执行、路由。扩展放在 /lib/<opcode>。
